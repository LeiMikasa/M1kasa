# 前后端联调说明

## 入口与范围

前端地址：http://localhost:5173/

当前已接通登录、店铺浏览、优惠券详情、秒杀预占和订单结果查询。

页面路径：附近 → 店铺详情 → 优惠券「查看详情」→ 登录后抢券 → 自动查询订单。

## 请求链路

```text
前端 → 网关 8080
          ├─ 用户服务 8081：验证码、登录、个人信息、退出
          ├─ 店铺服务 8082：分类、店铺、搜索
          ├─ 优惠券服务 8083：优惠券、秒杀预占
          └─ 订单服务 8084：当前用户的订单查询

Redis Lua 预扣库存并保存 Outbox
    → 后台任务发送 RabbitMQ 消息
    → 订单服务消费并落库
    → 前端查询到真实订单
```

## 本次新增接口

### 抢券

```http
POST /voucher/seckill/{voucherId}/reserve
Authorization: Bearer <token>
```

已有后端接口，现已在前端启用。请求成功代表获得资格，订单创建可能稍后完成。前端不会根据预占成功响应伪造订单。

### 查询我的对应优惠券订单

```http
GET /order/of/voucher/{voucherId}
Authorization: Bearer <token>
```

新增后端查询接口。用户身份从 Redis 中的登录态取得，客户端传入的 `userId` 或 `X-User-Id` 不作为查询身份。

尚无订单：

```json
{
  "success": true,
  "errorMsg": null,
  "data": null,
  "total": null
}
```

订单已创建：

```json
{
  "success": true,
  "errorMsg": null,
  "data": {
    "id": "1",
    "voucherId": "22",
    "status": 1,
    "createTime": "2026-10-26T22:01:18"
  },
  "total": null
}
```

ID 使用字符串，避免 JavaScript 大整数精度丢失。状态 1 为待支付、2 为已支付、3 为已取消。

`data=null` 本身不能区分未抢券与异步处理中的请求；页面结合本账号、本优惠券的提交记录展示待确认状态。

## 页面行为

- 未登录：引导登录，成功后返回优惠券详情。
- 提交中：防止重复点击，不自动重发抢券 POST。
- 获得资格或收到重复领取响应：查询已有订单，最多自动查询 12 次，每次响应后间隔 2 秒，并检查 30 秒截止。
- 自动查询结束：保留处理中或结果待确认提示，允许手动刷新。
- 网络结果未知：不宣称抢券失败或订单成功；查询仍无订单时，可由用户明确点击重新提交，后台不会自动重复提交。
- 离开详情、切换优惠券或账号：停止旧请求与轮询，清除旧页面中的订单展示。
- 刷新后重新进入同一张券：从后端恢复对应订单，不能仅凭本地标记认定订单已创建。
- 查到订单：展示真实订单 ID、状态和创建时间。

## 启动配置

订单服务新增 Redis 登录态验证，需连接与用户服务相同的 Redis 实例和逻辑数据库，使用相同的 `REDIS_PASSWORD`。网关已新增 `/order/**` 到 8084 的路由。

优惠券服务启用投递任务：

```yaml
m1kasa:
  seckill:
    outbox:
      enabled: true
```

仅在本地准备测试活动时，为优惠券服务启用 `local` profile，例如 IDEA 环境变量 `SPRING_PROFILES_ACTIVE=local`。创建和预热接口由 `@Profile("local")` 控制；不要将此配置当作正式的商家授权机制。

创建与预热接口分别为：

```http
POST /voucher/seckill
POST /voucher/seckill/{voucherId}/init
```

活动必须在开始前预热。不要重置已经开始活动的 Redis 库存来重复测试；应新建隔离的测试活动。
